# Принципы составления карты понятий

Карта понятий нужна не для красивой визуализации, а для явного описания структуры знания в курсе: какие понятия вводятся, какие понятия нужны для понимания других понятий, где есть пробелы и как материал развивается от занятия к занятию.

## Что такое карта понятий

**Карта понятий** (*concept map*) — это граф, в котором:

- узлы — понятия;
- связи — подписанные отношения между понятиями;
- каждая связь должна читаться как осмысленное утверждение.

Например:

```text
SPI -- используется для связи с --> ILI9341
Память МК -- нужна для понимания --> Цепочка загрузки RP2040
АЦП -- является примером --> Периферия микроконтроллера
```

Главное отличие карты понятий от интеллект-карты: в карте понятий важны не просто ассоциации, а точные отношения между понятиями.

## Фокус-вопрос

Перед построением карты нужно сформулировать вопрос, на который карта отвечает.

Для этого курса фокус-вопрос:

> Какие понятия нужны студенту, чтобы перейти от опыта работы с Raspberry Pi к разработке прошивки и устройств на RP2040?

Фокус-вопрос помогает не включать в карту случайные термины и бытовые примеры.

## Уровни карты

Полезно разделять два уровня:

- `macro` — крупные понятия, которые связывают несколько занятий или являются целями обучения;
- `micro` — частные понятия внутри одной темы, статьи или практической задачи.

Примеры `macro`:

- микроконтроллер;
- прошивка;
- периферия;
- память микроконтроллера;
- интерфейс;
- драйвер;
- уровни абстракции.

Примеры `micro`:

- MOSI;
- MISO;
- boot2;
- RGB565;
- GRAM;
- `gpio_set_function()`.

Практическое правило: если удаление понятия ломает понимание нескольких занятий, это `macro`. Если удаление ломает только один фрагмент объяснения, это `micro`.

## Роль понятия в курсе

Для каждого понятия полезно указывать его роль. Это не универсальная педагогическая классификация, а рабочая схема для курса микроконтроллеров.

Рекомендуемые роли:

- `предметная область` — широкие идеи: встраиваемая система, микроконтроллер, ВПО, прошивка;
- `железо` — физические и аппаратные сущности: пин, Flash, SRAM, АЦП, таймер;
- `протокол / интерфейс` — способы связи и договорённости обмена: GPIO, UART, SPI, I2C, USB;
- `архитектура ПО` — устройство программы и слои кода: драйвер, HAL, BSP, суперцикл, машина состояний, логгирование;
- `инструмент разработки` — внешние инструменты сборки, загрузки и отладки: компилятор, линкер, CMake, Make, picotool;
- `API / функция` — конкретные функции и программные интерфейсы: `gpio_init()`, `spi_write_blocking()`, `stdio_init_all()`;
- `учебный пробел` — понятие, которое нужно для понимания материала, но пока не раскрыто явно.

Такая классификация помогает увидеть перекосы: например, карта может стать слишком похожей на справочник API или, наоборот, не показывать конкретные инструменты, с которыми работает студент.

## Типы связей

Не стоит использовать слабую связь «связано с». Связь должна быть подписана так, чтобы из двух понятий и подписи получалось утверждение.

### Необходимо для понимания

Строгая пререквизитная связь.

```text
GPIO -- необходимо для понимания --> SPI
Память МК -- необходима для понимания --> Цепочка загрузки RP2040
```

Используется, когда без первого понятия второе трудно определить или объяснить.

### Определяется через

Обратная связь к пререквизиту.

```text
SPI -- определяется через --> GPIO
Драйвер внешней периферии -- определяется через --> I2C
```

Она помогает быстро увидеть, какие более сложные понятия опираются на данное понятие.

### Является частью

Иерархическая связь «часть — целое».

```text
GPIO -- является частью --> Периферия микроконтроллера
MOSI -- является частью --> SPI
```

### Является примером

Связь между общим понятием и конкретным примером.

```text
BME280 -- является примером --> Внешняя периферия
ILI9341 -- является примером --> Контроллер дисплея
```

### Используется для

Функциональная инженерная связь.

```text
SPI -- используется для --> Передача данных на дисплей
Логгирование -- используется для --> Отладка прошивки
```

### Влияет на

Динамическая связь, когда изменение одного параметра влияет на другое понятие.

```text
Частота SPI -- влияет на --> Скорость обновления дисплея
Период измерений -- влияет на --> Энергопотребление
Размер буфера -- ограничивается --> SRAM
```

### Полезно для понимания

Слабая cross-link связь между разными областями карты. Она не обязательна для определения, но помогает увидеть систему целиком.

```text
Логгирование -- полезно для понимания --> Отладка внешней периферии
Уровни абстракции -- полезны для понимания --> Драйвер BME280
```

## Траектория понятия по занятиям

Одно и то же понятие может играть разные роли в разных занятиях. Поэтому статус лучше привязывать не только к понятию целиком, а к его встречам в курсе.

Рекомендуемые статусы:

- `вводится` — понятие впервые объясняется;
- `закрепляется` — понятие повторяется и уточняется;
- `применяется` — понятие используется в практической задаче или в новой теме;
- `оценивается` — понимание понятия проверяется в задании или итоговой работе;
- `используется без явного определения` — понятие нужно студенту, но в материалах пока не раскрыто.

Пример:

```markdown
## Траектория по занятиям
- [[Как начать работать с микроконтроллерами]] / [[SPI]] — `вводится`
- [[Как работать с внешней периферией]] / [[Интерфейсы внешней периферии]] — `закрепляется`
- [[Как абстрагироваться от железа]] / [[Разбираемся с дисплеем]] — `применяется`
```

## Как выявлять пробелы

Понятие стоит пометить как пробел, если выполняется хотя бы одно условие:

- оно используется в определении другого понятия, но само не объяснено;
- оно нужно для выполнения задания, но не встречается в теории;
- оно появляется как технический термин без мотивации и примера;
- оно связывает несколько тем, но нигде не выделено как самостоятельное понятие;
- студент 1-2 курса, скорее всего, не сможет восстановить его из предыдущего опыта.

Пробел не означает ошибку курса. Это кандидат на будущую статью, вставку, пример или контрольный вопрос.

## Рекомендуемый шаблон файла понятия

```markdown
# Название понятия

## Уровень карты
- `macro` или `micro`

## Роль в курсе
- `предметная область`, `железо`, `протокол / интерфейс`, `архитектура ПО`, `инструмент разработки`, `API / функция`, `учебный пробел`

## Впервые встречается
- [[Название занятия]] / [[Название статьи]]

## Траектория по занятиям
- [[Занятие]] / [[Статья]] — `вводится`
- [[Занятие]] / [[Статья]] — `закрепляется`
- [[Занятие]] / [[Статья]] — `применяется`

## Понятия, которые определяются через это понятие
- [[...]]

## Понятия, необходимые для определения этого понятия
- [[...]]

## Полезные, но не обязательные связи
- [[...]]

## Общий статус
- `описано в курсе`, `используется без явного определения`, `пробел / стоит добавить`
```

## Практические рекомендации

1. Начинать с `macro`-карты курса, а не с полного списка терминов.
2. Для первой версии ограничить карту управляемым числом узлов.
3. Не заводить отдельный узел на каждую функцию API, если она не является учебной целью.
4. Разделять порядок изложения и логическую зависимость: если понятие встречается раньше, оно не обязательно является пререквизитом.
5. Подписывать связи глаголами или короткими фразами: «используется для», «является частью», «необходимо для понимания».
6. Проверять, читается ли связь как предложение.
7. Не смешивать строгие пререквизиты и полезные ассоциации.
8. Отдельно помечать понятия, которые курс использует без явного определения.
9. Периодически обновлять карту после изменения статей курса.
10. Использовать карту не только для навигации, но и для проектирования будущих обновлений курса.
